# AIエージェント共同型研究所：所長の役割を中心にした運用メモ

作成日: 2026-06-19 05:47 JST  
概要: Claude / Opus / Codex / ChatGPT を使って、よこぼのAIラボを「AIエージェント共同型研究所」として運用するための整理。特に、よこぼ自身が担うべき役割を重点的に記録する。

---

## 1. 今回の中心テーマ

Claude Opus と Codex を期間限定で使える状況を活かし、よこぼのAIラボをどのように発展させるかを整理した。

単に「AIに作業を代替させる」のではなく、以下の問いが重要になった。

> 自分はどこに入るべきか。  
> どこから先はAIに任せてよいのか。  
> AIエージェントと協働する研究所として、ラボ全体をどう設計するか。

その結果、最重要の整理として「ラボ憲章」と「よこぼがやるべきこと」の明文化が必要だとわかった。

---

## 2. 核となる合言葉

今回の議論で、よこぼのAIラボの中心に置くべき合言葉はこれ。

> AIは成果物を増やす。  
> よこぼは方向を決める。

これは単なる役割分担ではなく、ラボ全体の思想である。

AIは記事、動画、実験ログ、台本、README、パイプライン、素材整理などを増やせる。  
しかし、「何をやるか」「何を面白いと思うか」「どこに違和感があるか」「何を公開するか」は、よこぼが決める。

AIに任せるほど、よこぼは作業者ではなく、所長・観察者・判断者として振る舞う必要がある。

---

## 3. よこぼがやるべきこと

今回もっとも重要だと感じた概念。

よこぼがやるべきことは、完成物を全部自分で作ることではない。

### 3.1 何をやりたいかを決める

AIは「これが出せそう」「これを整理できます」と提案できる。  
しかし、それをやる意味が自分にあるかは、よこぼにしか決められない。

やることの例:

- ポッドキャストを続けるか
- よこぼのAIラボを研究所として育てるか
- 実験ログを公開するか
- ゲーム制作を進めるか
- 動画パイプラインを資産化するか
- 社内活動につなげるか

ここをAIに渡すと、ラボは便利な量産機にはなるが、「よこぼのAIラボ」ではなくなる。

### 3.2 最初の衝動を出す

AIは過去素材から提案はできるが、今この瞬間の反応は出せない。

よこぼが出すべきもの:

- これ面白い
- これやりたい
- なんか違う
- センスある
- 感激した
- これは自分の成長につながる気がする
- この違和感を残したい

この「最初の火種」がラボの起点になる。

### 3.3 違和感チェックをする

実験ログや動画パイプラインをAIが作ったとしても、最後に「これは自分の感覚とズレていないか」を見る必要がある。

見るべきポイント:

- 熱が死んでいないか
- きれいにまとまりすぎていないか
- 自分が言いたい芯が残っているか
- 公開して気持ち悪くないか
- よこぼのAIラボっぽいか

ここでの役割は、校正者ではなく「違和感センサー」。

文章の細かい修正を続けるのではなく、違和感の理由をAIに返して、次回のルールに変える。

### 3.4 公開する / 寝かせる / 捨てるを決める

AIはネタの熟度を判断できるが、最終的な公開判断はよこぼが行う。

判断の種類:

- 今すぐ出す
- もう少し育てる
- ポッドキャストで話してから出す
- 図解にする
- Codexに実装させる
- いったん寝かせる
- 捨てる

ここは研究所長の判断であり、AIに丸投げしない。

### 3.5 自分の成長につながる活動は手放しすぎない

ポッドキャストは成果物というより、よこぼ自身の思考トレーニングである。

そのため、台本をAIに作らせて読むだけになると意味が薄くなる可能性がある。

よこぼが担うべき部分:

- 話す
- 迷う
- 言葉に詰まる
- 言い直す
- 感覚を掘る
- 自分の声で考える

AIに任せてよい部分:

- 文字起こし整理
- タイトル案
- 説明欄
- note展開
- ショート動画台本
- サムネ案
- 実験ログ化
- 宣伝素材化

つまり、成長に効く摩擦は残し、作業の摩擦はAIに渡す。

---

## 4. AIエージェントの役割分担

### Claude / Opus

Claude / Opus は「編集長・研究企画室」。

役割:

- 思いつきやinboxを整理する
- 出せそうなテーマを提案する
- ネタの熟度を判断する
- 記事、台本、説明文、実験ログの初稿を作る
- ポッドキャスト文字起こしを素材化する
- Codex向けの小タスクに分解する
- 複数プロジェクトを横断して共通資産や改善点を見つける

注意点:

- 完成原稿へ閉じすぎない
- よこぼの衝動、違和感、未整理の熱を殺さない
- 公開判断を勝手にしない

### Codex

Codex は「工場長・整備士・実装担当」。

役割:

- ファイルやフォルダを整理する
- READMEやドキュメントを整備する
- スクリプトを作る
- Webサイト、ゲーム、動画、画像、音声の制作パイプラインを実装する
- inbox、assets、outputs、pipelinesを台帳化する
- 繰り返し作業を自動化する
- 作業結果を `_LAB_HQ` に報告する

Codexは一度に大きな夢を背負わせない。  
まずは小さなタスクを確実に終わらせる。

### ChatGPT

ChatGPT は「壁打ち相手・整理役・思考補助」。

役割:

- まだまとまっていない考えを広げる
- 言語化を手伝う
- 論点を整理する
- ClaudeやCodexに渡す依頼文を整える
- 必要に応じて批判的に検討する

---

## 5. 全体を見るエージェントと個別プロジェクトのエージェント

エージェントは全員が常に全体を見る必要はない。

理想は二層構造。

### 全体エージェント

`_LAB_HQ` を見る。

役割:

- ラボ全体の方針確認
- プロジェクト台帳の更新
- 優先順位の提案
- 出せそうなテーマの発見
- Codex向けタスクの整理
- 各プロジェクト間の接続

### 個別プロジェクトエージェント

各リポジトリや研究室を見る。

役割:

- 実装
- バグ修正
- README更新
- スクリプト作成
- 素材整理
- 動画生成パイプライン改善
- Webサイト更新
- ゲーム機能追加

最終形は「中央集権」ではなく「連邦制」。

`_LAB_HQ` が司令室。  
各repoが自治研究室。  
共通assetsやpipelinesが共有設備。  
outputsが公開展示室。

---

## 6. Playground整理の方針

現在、Playground配下には日付＋タイトル形式のrepoや実験フォルダが多数ある。

ゲーム、Webサイト、Blender、動画パイプラインなどが雑多に置かれている。

ただし、いきなり移動・改名・統合するのは危険。

理由:

- GitHub連携がずれる可能性がある
- Claude / Codex のプロジェクト紐づけが混乱する
- VS Code や GitHub Desktop の履歴がずれる
- スクリプト内のパスが壊れる可能性がある
- 整理作業が大きくなりすぎて止まる

したがって、最初にやるべきは物理的な整理ではなく、台帳化。

まず `_LAB_HQ` を作り、既存repoを動かさずに `PROJECT_INDEX.md` で見える化する。

---

## 7. 作成した `_LAB_HQ` の構成

今回、Codexへの最初の指示として、以下の司令室構成を作ることにした。

```text
_LAB_HQ/
  README.md
  LAB_CHARTER.md
  PROJECT_INDEX.md
  CODEX_QUEUE.md
  CLAUDE_BRIEF.md
  reports/
    .gitkeep
  templates/
    .gitkeep
```

役割:

- `README.md`：司令室の目的と基本フロー
- `LAB_CHARTER.md`：ラボの思想、役割分担、運用ルール
- `PROJECT_INDEX.md`：Playground配下のrepo台帳
- `CODEX_QUEUE.md`：Codexに投げる小タスク管理
- `CLAUDE_BRIEF.md`：Claude / Opus 用の共通ブリーフ
- `reports/`：作業結果や棚卸し報告
- `templates/`：今後のテンプレ置き場

---

## 8. Codexを詰まらせない考え方

Codexが稼働しない原因は、能力不足ではなく、タスクの粒度が大きすぎることにある。

Codex運用の原則:

- 1回1タスク
- 完了条件を明確にする
- 30分くらいで終わりそうな粒度に切る
- まずは整備仕事から始める
- 既存ファイルを壊さない
- 作業後は結果を報告する
- 大きな夢はClaudeに小タスクへ分解させる

Codexは「大工」より先に「研究所の整備士」として稼働させる。

---

## 9. 手直しの扱い

よこぼがAI生成物を手直しすること自体は悪くない。

ただし、毎回自分で直し続けると、よこぼが作業者に戻ってしまう。

今後は、手直しを単なる修正で終わらせない。

手直しから抽出するもの:

- 文体の好み
- 残したい熱量
- 削りたい表現
- 違和感が出たポイント
- 次回から守るべきルール

修正は「労働」ではなく「エージェント教育データ」として扱う。

---

## 10. 次のアクション

すでに `_LAB_HQ` v0.1 は作成済み。

次にやること:

1. `CODEX_QUEUE.md` の `001: Playground配下の棚卸し` を実行する
2. `PROJECT_INDEX.md` を更新する
3. repo / folder を `active / seed / archive_candidate / unknown` に分類する
4. 次に優先すべきCodexタスクを3つ出す
5. その結果をもとに、Claude / Opus が次の企画・整備方針を提案する

最初の棚卸しで完璧に分類しなくてよい。  
重要なのは、Playgroundを雑多なフォルダ群から、研究所の地図へ変えること。

---

## 11. 重要メモ

今回もっとも大事なのは、「よこぼがやるべきこと」の再定義。

よこぼの仕事は、全部を自分で作ることではない。

よこぼの仕事は、

- 衝動を出すこと
- やりたいことを決めること
- 違和感を拾うこと
- 成長に効く活動を手放しすぎないこと
- 公開判断をすること
- ラボの方向を更新すること

である。

AIは成果物を増やす。  
よこぼは方向を決める。

この分担ができると、よこぼのAIラボは「便利な自動化置き場」ではなく、AIと協働する個人研究所として回り始める。
