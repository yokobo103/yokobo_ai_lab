# HQ・Web連携契約

HQは意図と素材を整理する上流、Webサイトリポジトリは公開可能な形へ実装する下流です。この文書は、両者の引き渡し内容と判断境界を定めます。

## HQから渡すもの

- 目的
- 作業概要
- 原稿
- タイトル
- 一言説明
- 実験結果
- 使用画像
- 素材パス
- 公開判断（公開、下書き、よこぼ判断待ちなど）
- 触ってよい範囲
- 触ってはいけない範囲
- 停止ポイント（レビュー、push、merge、公開前など）

未確定の項目は、空欄にせず「未確認」または「よこぼ判断待ち」と明記します。

## Web側が行うこと

- ページ・UIを実装する
- `data/posts.json` の更新が必要か判断し、指定された範囲を守る
- 指定素材と画像パスを接続する
- レスポンシブ表示を確認する
- 可能な範囲で `npm run build`、`npm run lint`、`npm run typecheck` を実行する
- 変更内容、確認結果、未確認事項、残タスクを報告する

## 判断ルール

- 意図、原稿、素材、公開判断はHQを優先します。
- 表示、実装方法、既存コンポーネント、既存設計はWebサイトリポジトリを優先します。
- 不明点は推測で大きく進めません。影響を限定した小さい仮説として扱い、仮説・変更範囲・要確認事項を報告します。
- 既存URL、slug、公開済み投稿IDは不用意に変更しません。
- HQの指示とWeb側の既存仕様が衝突する場合は、公開影響のある変更を止め、差異をHQへ返します。
- `data/posts.json` を扱う場合は [posts_json_rule.md](./posts_json_rule.md) に従います。
