# 宣伝室（Promo Room）計画書 — Opus 5 引き継ぎ用

作成: 2026-07-26（Fable 5セッションでよこぼ承認済みの方針を文書化）
実装対象リポ: `20260428_webサイト刷新`（本番 https://yokobo-ai-lab.vercel.app/ ）

## 1. 背景とゴール

よこぼ（非エンジニア・スマホ運用）が「気が向いたときに」サイト全体の宣伝をXに投稿したい。
現状はadmin画面の記事ごとのXボタンしかなく、**画像付き投稿ができない**。

ゴール:
- スマホから、**サイト内のwebp画像を添付した宣伝投稿**が数タップで作れる
- 記事単位だけでなく「サイト全体の宣伝」「ランダムに過去実験を発掘」ができる
- 宣伝文はAIラボ側（Claude/Codexセッション）がストックを補充する形で連結する

## 2. 確定済みの方針（2026-07-26 よこぼ承認）

- **X APIは使わない**。developer登録・キー管理・無料枠制限を避ける
- 代わりに **Web Share API（`navigator.share({ files, text })`）** を使う。
  スマホの共有メニュー→Xアプリ→画像添付済み・文章入力済みの投稿画面が開き、
  最後の投稿ボタンはよこぼが押す（誤爆・自動投稿リスクなし）
- 進め方は **試作→よこぼのスマホで動作確認→本実装** の順
- 画像は断定で1枚選ばず **候補3〜4枚を提示してよこぼが選ぶ**
  （メディア台帳計画で決めた全セッション共通ルール。`_LAB_HQ` 参照）

## 4. 設計

### 画面: `/admin/promo`（モバイルファースト）

adminと同じパスワード認証。4ステップの縦一列UI（スマホ親指操作前提）。

1. **ネタ選択**: 「サイト全体」「最新記事」「ランダム実験発掘」「記事を選ぶ」のボタン
2. **画像選択**: ネタに応じた候補webpを3〜4枚グリッド表示、タップで1〜4枚選択。
   「別の候補」ボタンで引き直し
3. **文章選択**: テンプレ数種＋宣伝文ストック（後述）から選択、その場で編集も可
4. **シェア**: `navigator.share({ files, text })` を実行。
   - 事前に `navigator.canShare({ files })` でチェック
   - 使えない環境（PC等）では「文章をコピー＋画像をダウンロード」に自動フォールバック

### 画像一覧の取得

Vercel本番のserverless環境で `public/` をfs列挙するのは不確実なので、
**ビルド時にマニフェストを生成する**方式にする:
- `scripts/gen-image-manifest.mjs` が `public/**/*.webp` を走査して
  `data/promo-images.json`（パス・フォルダ分類・ファイルサイズ）を出力
- `package.json` の build に前段として組み込む
- admin画面から画像をアップロードした場合はGitHubコミット→再デプロイで反映される
  （即時反映は求めない。フェーズ1では割り切る）

### 宣伝文ストック（AIラボ連結の要）

- `data/promo-drafts.json`: `{ id, kind: "site"|"article"|"random", text, usedAt|null }` の配列
- AIラボ側のセッション（Claude/Codex）がこのJSONに新しい宣伝文を補充してコミットする。
  補充手順は本ドキュメントと `AGENTS.md` の慣例に従い、Codexでも書ける単純なJSON編集にする
- 使用済みは `usedAt` を記録（使ったかどうかはシェア実行時にAPIでマーク。
  GitHub保存の仕組みは `github_storage_guide.md` と同じ経路を使う）

### webpがXアプリに渡らなかった場合の保険

share sheet経由の挙動は機種・Xアプリのバージョン差がある。試作で確認すべき順:
1. webpのまま `files` に渡す（第一候補）
2. ダメなら Canvas でクライアント側 jpeg 変換してから渡す
3. `files` 自体が渡らないなら「画像は端末に保存＋文章は自動コピー→Xアプリで手動添付」に切替

## 5. 段階分け

### フェーズ0: share試作 — 実装済み（2026-07-26）

ページ: `app/experiments/share-test/page.tsx` → `/experiments/share-test`

PCブラウザで検証済みの内容:
- 共有可否の自動判定が正しく働く（共有機能のない端末では方式A〜Cを無効化し、
  「この端末では使えません（PCなど）」と表示）
- 画像の準備が成功（webp 337KB を取得 → jpeg 91KB に変換）
- 共有対応端末を再現したスタブで、方式A/B/Cが正しい中身を渡すことを確認
  （A=webpファイル＋文章＋URL、B=jpegファイル＋文章＋URL、C=文章のみ）
- 異常系の表示も確認（キャンセル／端末が形式を拒否／通信エラー）
- 方式Dは自動コピー失敗時に文章欄を表示して手動コピーできるようフォールバック

**残っているのは実機タップのみ**。Web Share APIはHTTPSでしか動かないため、
スマホで開くにはVercelデプロイかHTTPSトンネルが必要（LAN内のhttp://192.168...では
共有機能が無効になるので不可）。

以下は当初の想定手順（記録として残す）:
- 依存なしの単体ページ（例: `app/experiments/share-test/page.tsx` か静的HTML 1枚）に
  「固定のwebp1枚＋固定文章をシェア」ボタンだけ置く
- Vercelにデプロイし、**よこぼのスマホで1回タップしてもらう**のが唯一の確認事項。
  チャットでURLを渡し、結果（Xの投稿画面に画像と文章が両方入ったか）を聞く
- ここの結果で上記「保険」のどの方式にするか確定する

## 6. 制約・ルール（引き継ぎ先へ）

- よこぼは非エンジニア。**確認事項はチャットで完結**させる（ファイルを開かせない・
  スクショを撮らせない）。動作確認はURLを渡して結果を口頭で聞く形にする
- 画像は候補3〜4枚提示が原則。AIが1枚に断定しない
- 実装はCodexでも触れる単純さを保つ（`_LAB_HQ` の Codex実装可能性ルール）
- リポの `AGENTS.md` と `docs/codex_start_here.md` を先に読むこと
- X APIによる自動投稿は**不採用**（理由: 契約・キー管理の重さ、無料枠制限、
  自動投稿より「最後は人が押す」方が誤爆リスクゼロのため）。再検討するなら決裁に乗せる
